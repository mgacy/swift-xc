# swift-xc

A single SwiftPM package (Swift 6.2, macOS 15+) producing the `xc` CLI and the
`XCCore` library. Early development — there are no released consumers, so
backwards compatibility is not a concern. Break things when it makes the design
cleaner rather than adding compatibility shims.

## Agent configuration is generated — edit `.rulesync/`

`CLAUDE.md`, `AGENTS.md`, `.claude/`, and `.codex/` are **generated output**.
Editing them directly loses the change on the next generate. The sources of
truth are:

| To change | Edit | Then run |
|---|---|---|
| These instructions | `.rulesync/rules/*.md` | `mise run rulesync` |
| Hooks | `.rulesync/hooks.jsonc` + `.rulesync/hooks/*.sh` | same |
| Permissions | `.rulesync/permissions.jsonc` | same |
| Subagents / skills / MCP | `.rulesync/{subagents,skills,mcp.jsonc}` | same |

`rulesync doctor` is read-only and diagnoses the configuration.

Vendored upstream documentation for dependencies lives in
`docs/dependencies/`, pinned to the versions this project runs — consult it
instead of guessing at a dependency's file formats or CLI.

## Commands

```bash
swift build                       # debug build
swift test                        # run all tests
swift test --filter XCCoreTests   # filter by suite or test name
swift run xc --help               # exercise the CLI from source
```

Tooling is pinned in `.mise.toml`:

```bash
mise run lint                     # swiftlint
mise run lint-fix                 # swiftlint --fix
mise run lint-ci                  # actionlint + shellcheck (workflows and shell scripts)
mise run build                    # swift build -c release
mise run prepare-release patch    # open a version-bump release PR from local main
```

`Sources/xc/Version.swift` is generated by `swift-version-file-plugin` at
release time — never hand-edit it. `mise run prepare-release <patch|minor|major>`
creates the version-bump PR; after it merges, `.github/workflows/release.yml`
publishes an `xc-macos-arm64` asset plus `SHA256SUMS`.

Editing `.mise.toml` or `.mise.local.toml` requires approval, because the
session-start hook trusts a worktree's mise config when it matches the main
checkout — an edit there becomes code that later runs.

## Code search

`sextant` (pinned in `.mise.toml`) is a structural Swift search tool. Use
`--pretty` for readable output.

```bash
mise x -- sextant lookup XCCore --pretty                  # definition site, conformances, extensions
mise x -- sextant lookup run --kind function --pretty
mise x -- sextant enum-cases Sources --enum-name Error --pretty   # cases with associated values
mise x -- sextant overview Sources/XCCore/XCCore.swift --pretty   # structure of a file or directory
mise x -- sextant references XCCore --path Sources --pretty       # declaration-level references
mise x -- sextant references Codable --path Sources --position inheritance --pretty
```

**Prefer sextant over Grep for:** where a type is defined; the cases of an enum
(regex is brittle against associated values); the structure of a file; where a
type is referenced in declarations; what conforms to a protocol.

**Use Grep instead for:** anything inside function bodies, comments, or string
literals, and for non-Swift files.
